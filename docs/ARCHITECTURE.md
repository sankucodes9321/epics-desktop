# Architecture and trust boundaries

The Fedora session and camera driver deliver BGR pixels to a local GStreamer subprocess. Its stdout is a pipe into an application-owned array. After 30 frames the last full frame enters the capture context. The OpenCV fallback stays local. Capture, subprocess and scratch-buffer cleanup run on errors and interrupts.

DeepFace receives the RAM frame. RetinaFace supplies candidate geometry, confidence and RGB crops. FasNet analyzes the original frame and bounding box at two scales. Exactly one candidate must pass confidence and minimum size. Liveness, brightness, centering and sharpness gate representation. Facenet512 uses the accepted crop with detector_backend=skip. TensorFlow, torch and native libraries share the process trust boundary.

Enrollment normalizes a 512-element float32 probe, authenticates existing templates, checks enrollment consistency and encrypts the updated matrix with AES-256-GCM and a fresh 96-bit nonce. Associated data includes user ID, template count, dimension and model. Verification and identification decrypt into caller-owned RAM and compute cosine scores. Redis transactions check for competing enrollment, rotation or lockout changes. Daily attendance uses atomic insert-if-absent.

Redis and its backups see ciphertext plus names, IDs, template counts, timestamps, scores and events. The configured key lives on the trusted host. A stolen database alone does not expose plaintext vectors. GCM detects modified ciphertext or associated data. Host compromise, key theft, deletion, replay of an earlier database, modified display names and observation of process memory remain outside that protection. Attendance exports contain identifying metadata. See SECURITY.md for swap, memory locking and core dumps.

A one-to-many decision reads the revision, scans the records, authenticates each normalized matrix and scores one probe. It compares the best score for each distinct user. A transaction rechecks the revision before logging even an unknown result. For a unique winner it also rechecks the ciphertext and lockout. Attendance uses the configured local calendar day as the hash suffix, stores UTC ISO time, and displays both UTC and local offsets. A duplicate returns the time of the original event.

The operator supplies the persistent AES key independently of Redis. Key rotation stages verified ciphertext and changes records plus the key fingerprint in one transaction. CLI deletion opens and authenticates the target record before committing. GStreamer runs with a limited session environment. The capture sequence, RGB crop path, 512-float encoding and v1 associated data remain compatible with existing enrollments.

The teacher GTK process sends one request at a time to a persistent CPU worker over private pipes. The worker reuses the gallery matcher. A lecture mark watches the lecture record in the same transaction as the winning identity and lockout checks. Finalization signs a Merkle root over per-event commitments. Session data uses a separate namespace from daily attendance. The portable verifier consumes a student receipt, a public document and the independently trusted school public key. It has no connection to the teacher database.
